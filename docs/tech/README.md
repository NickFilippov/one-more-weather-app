# Техническая документация OneMoreWeatherApp

Как построить приложение: архитектура, источники данных, правила, перенос дизайна и пошаговый план. Бизнес-документы (что и зачем) лежат уровнем выше, в [docs/](../README.md); здесь — как.

Документы написаны так, чтобы по ним можно было работать задача за задачей, не принимая архитектурных решений и не имея доступа к приватным артефактам дизайна: все числа, цвета, SVG-пути и тестовые данные перенесены сюда.

Версия 1.0, 2026-10-27.

## Главные решения

- **Expo Router**, маршруты в `src/app/`: `index` (города листаются свайпом), `cities` (список и поиск).
- **Погода и поиск городов: Open-Meteo**, без ключа и без своего сервера. Один запрос на город даёт текущую погоду, 24 часа, 10 дней, восход и закат.
- **Картинки не нужны:** небо, облака, дождь и иконки рисуются кодом (Skia, SVG). Шрифт цифр — Bricolage Grotesque из `@expo-google-fonts`.
- **Стекло:** `GlassView` на iOS 26+, иначе `BlurView` с тёмной тонировкой. Выбор по `isLiquidGlassAvailable()`, не по платформе.
- **Состояние:** `zustand` + `persist` поверх `expo-sqlite/kv-store`. Данные старше 30 минут перезапрашиваются, без сети показываются последние.
- **Предупреждения отложены** (решение владельца). Карта осадков и правка списка — после первой версии.

## Как работать по этим документам

1. Возьми следующую задачу из [05](05-implementation-plan.md) по порядку. Не начинай задачу следующего этапа, пока не закрыт текущий (исключение: T-40…T-45 можно делать параллельно с этапами 2–3).
2. Прочитай разделы, на которые ссылается задача. Значения бери оттуда, не придумывай.
3. Перед тем как писать код с API Expo или React Native, открой документацию **SDK 58** (`https://docs.expo.dev/versions/v58.0.0/…`) для этого модуля и сверь имена. Не пиши по памяти (так требует `AGENTS.md`).
4. Пакеты ставь только `npx expo install <пакет>`. Не `npm install`, не `yarn add`.
5. Не создавай и не правь `ios/` и `android/`: они генерируются.
6. Сделай задачу целиком, пройди [Definition of Done](#definition-of-done), закоммить.
7. Если документ и реальность расходятся (API изменился, значение не подходит на устройстве), поправь документ в том же коммите и напиши почему.
8. Если нужно решение, которого нет ни здесь, ни в [docs/07](../07-risks-and-open-questions.md), не выбирай сам: остановись и спроси владельца.

### Чего не делать

- Не подключать сторы и API в `src/components/` (правила зависимостей в [01](01-architecture.md#правила-зависимостей)).
- Не задавать `fontFamily` системному тексту и `fontWeight` тексту Bricolage.
- Не проверять `Platform.OS`, чтобы выбрать стекло.
- Не менять `opacity` у `GlassView`.
- Не класть стекло на стекло.
- Не писать текст цветами `rain`, `cold`, `warm`; не ставить `textMuted` над `skyTop`.
- Не использовать эмодзи и советы в текстах; минус только `−`, градус без пробела.
- Не добавлять библиотеки сверх списка в [01](01-architecture.md#зависимости) без согласования.

## Definition of Done

Задача закрыта, когда:

1. Выполнены все пункты «Готово, когда» этой задачи.
2. `npx tsc --noEmit` — без ошибок.
3. `npx expo lint` — без ошибок (с этапа 0, T-05).
4. `npx jest` — все тесты проходят (с T-06); новая логика покрыта тестами по [06](06-testing.md).
5. `npx expo-doctor` — без ошибок, если менялись зависимости или `app.json`.
6. Если менялся UI: экран проверен на iOS и Android и сравнён со скриншотом макета.
7. Если поменялось поведение: обновлены [docs/03](../03-functional-requirements.md), [docs/06](../06-business-rules-and-data.md) или [docs/07](../07-risks-and-open-questions.md), а также этот раздел документации.
8. Тексты для пользователя на русском и лежат в `src/i18n/ru.ts`.
