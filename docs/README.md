# Документация OneMoreWeatherApp

Бизнес-документация проекта: что за продукт, для кого он, что должен уметь и какие вопросы ещё открыты. Документы описывают задуманное поведение. В коде пока ничего из этого не реализовано (стартовый шаблон Expo), поэтому везде, где сказано «должно», речь о требованиях, а не о готовой функциональности.

Версия 0.1, черновик для согласования с автором проекта. Дата: 2026-10-26.

## Как читать

- **Идентификаторы.** US: пользовательская история, FR: функциональное требование, NFR: нефункциональное, BR: бизнес-правило, R: риск, Q: открытый вопрос, A: допущение. На них документы ссылаются друг на друга.
- **Приоритеты** по MoSCoW: Must (обязательно для первой версии), Should (важно, но без этого первую версию выпустить можно), Could (желательно), Won't (сознательно не делаем сейчас).
- **Что факт, а что предположение.** Факт взят из дизайна или кода. Всё, чего автор не говорил и в дизайне нет, помечено словом «Предположение» и вынесено в [открытые вопросы](07-risks-and-open-questions.md). Целевые значения (скорость, частота обновления) тоже предложены аналитиком и ждут подтверждения.
- **Статус дизайна** у требований: «есть» (экран нарисован), «частично» (нарисована часть), «нет» (дизайна нет).
